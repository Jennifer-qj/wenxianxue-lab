# 《文献学实验室》项目报告

## 项目摘要

《文献学实验室》是一个面向大学生与文献学初学者的独立数字人文学习项目。项目参考杜泽逊《文献学概要（修订本）》，但不复刻原书全文，而是将十四章内容转化为学习单元、概念词条、知识关系、结构化练习、互动案例和人工复核状态。

项目的核心研究问题是：怎样在尊重版权与学术边界的前提下，把一本专业教材变成可探索、可练习、可复核的学习系统？

## 目标与受众

- 主要受众：第一次至第三次阅读《文献学概要》的大学生与初学者。
- 学习目标：建立全书结构，理解跨章关系，练习证据判断，并形成可持续复习的个人档案。
- 成果目标：形成一项能够展示内容建模、教学设计、前端实现与数字人文方法的个人作品。

## 方法

1. 以纸本目录和章节为内容边界。
2. 将章节拆分为最小学习单元（MKU）。
3. 提取概念、载体、典籍、人物、事件和方法。
4. 为跨概念关系记录类型、证据与置信度。
5. 将知识转译为选择、配对、排序、分类、证据判断与开放作答。
6. 设计知识图谱、学习路径、综合案卷和本地学习档案。
7. 通过状态字段区分“结构化完成”与“纸本核验完成”。
8. 通过公开反馈、版本历史和审计页面持续修订。

## 核心成果

- 十四章全覆盖与七条重组学习路径。
- 学习单元、独立概念页、跨章知识图谱和可导出子图。
- 九种题型、三级开放题参考答案与自动错题本。
- 古籍鉴定综合案卷，以及面向目录、版本、校勘、载体的互动任务。
- 无登录的札记、收藏、最近浏览、进度与导入导出。
- 公开内容审计、纸本复核队列、反馈共校流程和贡献规范。
- 响应式界面、键盘操作、减少动态与无障碍说明。

项目规模应以网站“项目展示”页和仓库当前版本的自动统计为准，避免在静态报告中固化过时数字。

## 数据与技术架构

内容以 YAML 结构化保存，页面使用 Astro 构建，互动组件使用 React。所有页面静态生成并由 GitHub Pages 托管。学习记录只保存在浏览器本地，不设置账号与后端数据库。

内容关系为：章 → 学习单元 → 概念 → 关系 → 题目／实验 → 复核状态。

质量流程包括：模式校验、内容一致性检查、组件测试、静态构建、断链检查和 GitHub Actions 自动部署。

## 本人贡献

- 确定项目问题、用户、边界和评价标准。
- 设计全书内容模型、元数据、复核状态与贡献机制。
- 将阅读材料转化为概念、关系、练习和互动案例。
- 设计界面信息架构、学习闭环和展示叙事。
- 组织自动化检查、发布、版本记录与后续维护。

项目采用人机协作：AI用于辅助结构化、交互原型、代码实现和一致性检查；项目作者决定研究目标、内容边界，并承担最终纸本复核和公开发布责任。

## 局限与伦理

- 全书结构化覆盖不等于所有表述已经完成纸本复核。
- 远程书影、OCR 与自动生成内容只作为工作材料，不自动成为学术证据。
- 公开仓库不保存原书 OCR、扫描件或大段逐字转录。
- 学习案例与真实馆藏材料必须明确区分。
- 共校意见需要证据和版本记录，不以多数票代替学术判断。
