# 《文献学实验室》面试／答辩展示脚本

## 三分钟版本

### 第一分钟：问题与选择

我做的是一个面向文献学初学者的数字人文学习网站。项目起点不是“把一本书搬到网上”，因为在线电子书仍然只能顺序翻阅，也很难训练版本、校勘和目录中的判断过程。

因此我提出的问题是：能不能在不公开原书全文的前提下，把《文献学概要》的知识重新组织成可探索、可练习、可复核的学习系统？目标用户是第一次到第三次阅读这本书的大学生。

### 第二分钟：方法与实现

我先设计内容模型，再做页面。我把十四章拆成学习单元、概念、知识关系、题目、实验和复核状态。每个概念可以跨章关联，每条图谱关系保留证据与置信度；题目不只有选择题，也包括排序、分类、证据判断和开放作答。

前端形成了七条学习路径、可拖动知识图谱、综合鉴定案卷、九题型练习和无登录学习档案。技术上使用 Astro、React、结构化 YAML 与 GitHub Pages，并建立内容校验、测试、断链检查和自动部署。

### 第三分钟：价值与反思

这个项目的价值不只在于页面数量，而在于它公开了知识怎样被转译、审核和修订。网站明确区分“十四章已经结构化覆盖”与“纸本已经逐条核验”，还提供审计页、版本历史与读者共校入口。

项目使用了 AI 辅助结构化和代码实现，但研究问题、内容边界、教学判断与最终纸本复核由我负责。对我而言，它同时是一个学习工具、一项数字人文实验，也是一份可以继续生长的公共作品。

## 一分钟精简版

《文献学实验室》是我把《文献学概要》转化为互动学习系统的一次数字人文实践。它不是原书电子版，而是用学习单元、知识图谱、九题型练习、综合案卷和本地学习档案重组全书。项目特别保留证据、置信度和纸本复核状态，并开放读者共校。我负责研究策划、内容模型、学习设计、界面实现与发布维护；AI用于辅助结构化和代码，但最终学术责任由我承担。

## 常见追问

### 为什么不用登录和数据库？

这是学习型静态网站，不需要收集用户身份。进度、错题和札记保存在浏览器本地，降低隐私、运维和成本负担，也符合个人项目边界。

### 怎样证明覆盖全书？

覆盖矩阵和审计页按十四章检查学习单元、概念、题目、实验和深度研读；但覆盖不等于核验，精确页码仍按状态逐条完成。

### AI 做了什么？

AI辅助结构拆分、代码实现、文案重写和一致性检查。研究目标、版权边界、内容取舍、教学机制和最终学术复核由项目作者决定并负责。

### 最大难点是什么？

不是搭页面，而是把连续论述转成仍然保留证据边界的数据结构；同时要避免把教学简化写成绝对结论，把“看起来完整”误当成“已经学术核验”。

### 下一步是什么？

继续纸本复核、扩充非选择题和高质量案例，并邀请实际读者参与章节共校和无障碍测试。
